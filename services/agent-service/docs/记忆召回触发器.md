# Memory 召回触发策略：生产方案

> 解决问题：每轮 message 到来时，如何以最低成本准确判断是否需要触发记忆召回

---

## 一、核心思路：分层漏斗

不用单一方案解决所有情况，而是按成本从低到高逐层过滤，早命中早退出。

```
消息到达
    │
    ▼
┌─────────────────────────────────┐
│  Layer 1：规则层                │  < 1ms，零模型成本
│  关键词 / 轮次 / 复杂度         │
└────────────┬────────────────────┘
             │ 未命中
             ▼
┌─────────────────────────────────┐
│  Layer 2：Embedding 相似度      │  ~5ms，复用召回侧向量
│  当前消息 vs L1 buffer          │
└────────────┬────────────────────┘
             │ 仍不确定
             ▼
┌─────────────────────────────────┐
│  Layer 3：轻量分类模型          │  10–30ms，可选
│  zero-shot 意图分类             │
└────────────┬────────────────────┘
             │ 最终兜底
             ▼
┌─────────────────────────────────┐
│  Layer 4：LLM Tool-call         │  200ms+，高价值场景
│  search_memory 工具自主触发     │
└─────────────────────────────────┘
```

每层命中即触发召回并**跳过后续层**，未命中才向下传递。

## 二、Layer 1：规则层

### 2.1 关键词/正则匹配

维护一份触发词表，扫描当前消息：

```python
RECALL_TRIGGERS = [
    # 显式历史引用
    r"上次", r"之前", r"你还记得", r"我之前(说|提|讲|告诉你)",
    r"继续", r"接着", r"刚才", r"前面",
    # 隐式代词引用（需结合上下文判断）
    r"那个(事|问题|方案|人)",
    r"还是.*那个", r"和之前一样",
    # 英文
    r"last time", r"as I mentioned", r"remember when",
    r"you said", r"we discussed", r"earlier",
]

def rule_trigger(message: str) -> bool:
    for pattern in RECALL_TRIGGERS:
        if re.search(pattern, message):
            return True
    return False
```

**覆盖率**：显式引用场景 ~60–70%

### 2.2 强制触发规则

```python
def force_trigger(turn_index: int, message: str, token_count: int) -> bool:
    # 首轮强制：预热 L1 缓存
    if turn_index == 0:
        return True
    # 长间隔强制：每 10 轮触发一次防止上下文漂移
    if turn_index % 10 == 0:
        return True
    # 复杂消息：token 数超阈值，通常意味着复杂任务
    if token_count > 200:
        return True
    return False
```

### 2.3 实体密度检测（NER，轻量）

使用小型 NER 模型（spaCy `zh_core_web_sm` 或 `en_core_web_sm`）检测消息中是否出现用户相关命名实体：

```python
import spacy
nlp = spacy.load("zh_core_web_sm")

def ner_trigger(message: str, user_entities: set) -> bool:
    """user_entities 来自 L3 用户档案中已知的人名/项目名/地点"""
    doc = nlp(message)
    for ent in doc.ents:
        if ent.text in user_entities:
            return True
    return False
```

## 三、Layer 2：Embedding 相似度判断

### 核心思路

当前消息 embed 后，和 L1 buffer 中最近 N 轮的 embedding 做余弦相似度计算：

- **相似度高**（> 阈值）→ 对话连续，无需拉历史
- **相似度低**（< 阈值）→ 话题跳跃，可能需要历史上下文

**关键优势**：做 L2 向量召回本身就需要 embed 当前消息，这一步可以**零额外成本**复用该向量。

```python
import numpy as np

def embedding_trigger(
    current_embedding: list[float],
    l1_buffer_embeddings: list[list[float]],
    threshold: float = 0.75,
    window: int = 3,
) -> bool:
    """
    current_embedding: 当前消息的 embedding
    l1_buffer_embeddings: L1 中最近 N 轮消息的 embeddings
    threshold: 相似度低于此值则触发召回
    """
    if not l1_buffer_embeddings:
        return True  # 无历史，触发初始化召回

    recent = l1_buffer_embeddings[-window:]
    similarities = [
        np.dot(current_embedding, e) /
        (np.linalg.norm(current_embedding) * np.linalg.norm(e))
        for e in recent
    ]
    avg_similarity = np.mean(similarities)
    # 相似度低 → 话题跳跃 → 需要召回
    return avg_similarity < threshold
```

### 阈值调参建议

| 场景 | 推荐阈值 |
|------|----------|
| 闲聊型产品（话题多变） | 0.65 |
| 任务型 Agent（话题聚焦） | 0.80 |
| 通用 | 0.75 |

## 四、Layer 3：轻量意图分类模型

### 4.1 Zero-shot 分类（无需标注数据）

使用 `sentence-transformers` + zero-shot 分类，将消息归为四类：

```python
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

INTENT_LABELS = {
    "new_topic":    "用户提出了一个全新的问题或话题",
    "continuation": "用户在延续之前的对话内容",
    "history_ref":  "用户明确引用或询问过去发生的事情",
    "chit_chat":    "用户在进行日常闲聊",
}

RECALL_INTENTS = {"new_topic", "history_ref"}  # 这两类需要触发召回

def intent_trigger(message: str) -> tuple[str, bool]:
    msg_emb = model.encode([message])
    label_embs = model.encode(list(INTENT_LABELS.values()))
    scores = cosine_similarity(msg_emb, label_embs)[0]
    intent = list(INTENT_LABELS.keys())[np.argmax(scores)]
    return intent, intent in RECALL_INTENTS
```

### 4.2 Sliding Window 上下文感知（更准确）

不只看当前消息，将最近 3–5 轮 + 当前消息一起送入分类，判断"是否需要超出当前 window 的信息"：

```python
def context_aware_trigger(
    recent_turns: list[str],
    current_message: str,
    model,
    threshold: float = 0.6,
) -> bool:
    context = "\n".join(recent_turns[-4:]) + "\n用户：" + current_message
    query = "这段对话需要引用当前窗口之外的历史信息"
    ctx_emb = model.encode([context])
    qry_emb = model.encode([query])
    score = cosine_similarity(ctx_emb, qry_emb)[0][0]
    return float(score) > threshold
```

## 五、Layer 4：LLM Tool-call（兜底 / 高价值场景）

将记忆召回建模为工具，LLM 在推理时自主决定是否调用：

```python
tools = [
    {
        "name": "search_memory",
        "description": (
            "当需要用户的历史信息、偏好、过往对话内容时调用。"
            "若当前消息可以仅凭上下文窗口内的信息回答，则不调用。"
        ),
        "input_schema": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "用于检索历史记忆的语义查询词"
                }
            },
            "required": ["query"]
        }
    }
]
```

LLM 不 emit `tool_use` block → 记忆层完全不触碰，无任何额外开销。

**适用场景**：对召回精度要求极高，或记忆召回代价很高（如大规模向量库）的场景。

## 六、完整流水线实现

```python
class MemoryRecallDecider:
    def __init__(self, embed_model, nlp_model, user_entities: set):
        self.embed_model = embed_model
        self.nlp_model = nlp_model
        self.user_entities = user_entities

    def should_recall(
        self,
        message: str,
        turn_index: int,
        l1_buffer: list[dict],  # [{"text": ..., "embedding": ...}]
    ) -> tuple[bool, str]:
        """
        Returns:
            (should_recall: bool, reason: str)
        """
        token_count = len(message.split())

        # Layer 1a: 强制触发
        if force_trigger(turn_index, message, token_count):
            return True, "force_rule"

        # Layer 1b: 关键词规则
        if rule_trigger(message):
            return True, "keyword_rule"

        # Layer 1c: NER 实体检测
        if ner_trigger(message, self.user_entities):
            return True, "ner_entity"

        # Layer 2: Embedding 相似度
        current_emb = self.embed_model.encode([message])[0]
        buffer_embs = [t["embedding"] for t in l1_buffer]
        if embedding_trigger(current_emb, buffer_embs):
            return True, "embedding_drift"

        # Layer 3: 轻量意图分类
        recent_texts = [t["text"] for t in l1_buffer[-4:]]
        if context_aware_trigger(recent_texts, message, self.embed_model):
            return True, "intent_classifier"

        # 所有层均未触发
        return False, "no_recall_needed"
```

## 七、各方案效果对比

| 方案 | 延迟 | 召回率 | 误召回率 | 额外成本 | 推荐场景 |
|------|------|--------|----------|----------|----------|
| 纯规则 | < 1ms | ~65% | 低 | 零 | 资源极度受限 |
| 规则 + NER | ~5ms | ~75% | 低 | 极低 | 轻量生产 |
| 规则 + Embedding | ~5ms | ~85% | 低中 | 近零（复用） | **大多数生产场景** |
| 规则 + Embedding + 分类模型 | ~30ms | ~92% | 中 | 低 | 精度优先 |
| LLM Tool-call | 200ms+ | ~95% | 最低 | 高 | 高价值 / 兜底 |

## 八、架构简化特例

### L1 + L3 架构（无 L2）

若已裁剪 L2，召回判断层大幅简化：

- **L3 注入**：session 级全量注入 system prompt，无需逐轮判断
- **工具调用**：外部知识获取交由 LLM tool-call 自主决定
- **结论**：整个召回触发层可以省掉，工程复杂度显著降低

```
消息到达 → 直接进 LLM（携带 L3 profile）
              │
              └─ LLM 自主决定是否调用外部工具
```

## 九、冷启动与降级策略

```python
def recall_with_fallback(decider, message, turn_index, l1_buffer):
    try:
        should, reason = decider.should_recall(message, turn_index, l1_buffer)
        metrics.record("recall_decision", reason=reason, triggered=should)
        return should
    except EmbeddingServiceError:
        # Embedding 服务故障 → 降级到纯规则
        logger.warning("Embedding service down, falling back to rule-only")
        return rule_trigger(message) or force_trigger(turn_index, message, len(message.split()))
    except Exception as e:
        # 未知错误 → 保守策略：触发召回
        logger.error(f"Recall decider failed: {e}")
        return True
```

**降级原则**：宁可多召回（假阳性），不可漏召回（假阴性）。多召回最多增加延迟，漏召回会直接影响回答质量。
