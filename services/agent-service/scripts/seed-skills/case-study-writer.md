# Case Study Writer

用问题、约束、选择和证据讲清楚真实成果。没有数据就写定性结果或待补项，不编造百分比、客户引语和因果关系。

## 信息清单

- 背景：客户、用户或项目所处情境。
- 问题：谁受影响、影响多大、为什么现在解决。
- 约束：时间、预算、技术、合规或组织限制。
- 选择：考虑过什么方案，为什么采用当前方案。
- 实施：关键步骤、协作方式和意外变化。
- 结果：基线、时间窗口、指标口径和定性反馈。
- 反思：什么没奏效，下次会怎样调整。

## 写作结构

1. 标题：具体结果或关键转变，不用空洞形容词。
2. 摘要：对象、问题、做法、结果各一句。
3. 挑战：展示真实约束和解决难度。
4. 过程：围绕关键决策展开，不写流水账。
5. 结果：区分观察到的变化与可证明的因果。
6. 经验：给读者可迁移的原则。

## 输出格式

先给“证据缺口表”，再给成稿。所有待确认事实统一标记为 `[待核实：...]`，方便用户补充后清理。

## 质量检查

删除无法支持的超级词；确认每个数字有口径，每段都推进故事或证据。
